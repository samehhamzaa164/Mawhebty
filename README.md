# موهبتي | Mawhebty

منصة عربية كاملة لاكتشاف مواهب الأطفال وتنميتها: اختبار اهتمامات، مكتبة مواهب، مسارات تعليمية تفاعلية، تحديات، نقاط وشارات، مساعد تعليمي آمن، لوحة لولي الأمر، ولوحة إدارة حقيقية.

> **حالة المشروع:** تطبيق محلي عامل بالكامل على قاعدة SQLite. لم يُنشر على نطاق عام، ولم تُربط به خدمات سحابية أو مزودو ذكاء اصطناعي أو بريد إلكتروني. كل ما يلي يصف ما تم تنفيذه واختباره فعليًا داخل هذا المستودع.

## أبرز الميزات

### للطفل
- **اختبار اكتشاف الاهتمامات:** 10 أسئلة باختيار من متعدد، حساب النتائج على الخادم، توصيات مع درجة توافق، وملخص تربوي. النتيجة استكشافية وليست تشخيصًا.
- **مكتبة المواهب:** 29 موهبة موزعة على 5 مجالات (فنية، علمية وتقنية، رياضية، اجتماعية وقيادية، عملية وحياتية) مع صفحة تفاصيل لكل موهبة.
- **مسارات تعليمية:** خريطة مراحل، فتح تدريجي للمراحل من الخادم، دروس ومحتوى وأمثلة وأنشطة، ثم تحدي قصير.
- **تحفيز حقيقي:** XP يُمنح مرة واحدة لكل مرحلة عبر معاملة خادمية، شارات تلقائية، واستريك يومي محفوظ.
- **تحديات وأنشطة:** إرسال إنجاز نصي مع حالة مراجعة، دون منح نقاط مكررة.
- **مساعد نوري:** محادثة عربية آمنة للأطفال، حد استخدام، فلترة للمحتوى غير المناسب، ووضع محلي احتياطي يعمل بدون أي مفتاح.
- **ملف شخصي وإعدادات وإشعارات:** الاسم والصورة الرمزية، تفضيلات اللغة والصوت والإشعارات، وصندوق إشعارات داخل المنصة.

### لولي الأمر
- **الوحة متابعة:** عرض كل طفل على حدة، XP، المراحل المكتملة، الشارات، عدد الاختبارات، والاستريك.
- **نتائج الاكتشاف:** آخر توصيات الاختبار مع تنبيه واضح أنها للتوجيه فقط.
- **إدارة الأطفال:** إضافة طفل جديد باسم مستخدم ورمز دخول، وتعديل الاسم والعمر والصورة الرمزية.
- **خصوصية:** لا يرى ولي الأمر كلمة مرور الطفل، ولا تُعرض ملفات الأطفال للعامة.

### للمسؤول
- **نظرة عامة:** إحصاءات المستخدمين والمواهب والمراحل والإكمالات، نشاط 7 أيام، وتوزيع المواهب.
- **إدارة المواهب:** إنشاء وتعديل وأرشفة/استعادة، مع أوصاف ومهارات وأمثلة وأيقونات وألوان وترتيب.
- **إدارة المحتوى:** تعديل المراحل والدروس والتحديات ومكافآت XP ونشرها أو إلغاء نشرها، مع تصفية حسب الموهبة.
- **بنك الأسئلة:** تعديل صياغة السؤال والتلميح والترتيب، تفعيل/تعطيل الأسئلة، مع حماية أوزان التقييم من التعديل.
- **إدارة المستخدمين:** بحث وتصفية حسب الدور، إيقاف/تفعيل الحساب (مع إنهاء الجلسات)، ومسح محادثات نوري.
- **سجل عمليات:** تسجيل خادمي لكل عملية إدارية مع اسم المسؤول والوقت والتفاصيل.

## التشغيل السريع

### المتطلبات
- **Node.js 22.5 أو أحدث** (يُفضّل Node 24). المشروع يستخدم `node:sqlite` المدمج، لذلك لا يحتاج تثبيت قاعدة بيانات منفصلة.
- npm 10 أو أحدث.

تم تطوير المشروع والتحقق منه على **Node v24.21.0** و **Next.js 15.5.29** و **React 19**.

### الخطوات

```bash
# 1) تثبيت الحزم
npm install

# 2) إنشاء ملف البيئة المحلي
# Windows PowerShell:
Copy-Item .env.example .env.local
# macOS / Linux:
cp .env.example .env.local

# 3) تشغيل التطوير
npm run dev
```

افتح [http://localhost:3000](http://localhost:3000).

عند أول طلب يهيئ التطبيق قاعدة البيانات تلقائيًا في `data/mawhebty.db` ويزرع البيانات الأولية وحسابات العرض. لا تحتاج إلى تشغيل أوامر ترحيل يدويًا.

### بناء الإنتاج محليًا

```bash
npm run build
npm run start
```

> الإنتاج هنا محلي فقط. لم يتم نشر التطبيق على Vercel أو أي مزود استضافة.

### إعادة تعيين قاعدة البيانات

أوقف الخادم ثم احذف ملفات قاعدة البيانات:

```powershell
Remove-Item data\mawhebty.db, data\mawhebty.db-wal, data\mawhebty.db-shm -ErrorAction SilentlyContinue
```

سيُعاد إنشاء القاعدة والبيانات الأولية عند التشغيل التالي. **تحذير:** هذا يحذف كل الحسابات والتقدم والعمليات المسجلة.

## متغيرات البيئة

انسخ `.env.example` إلى `.env.local`. كل المتغيرات اختيارية ما عدا `SESSION_SECRET` في الإنتاج.

| المتغير | مطلوب | الوصف |
|---|---|---|
| `DATABASE_PATH` | لا | مسار قاعدة SQLite. الافتراضي `./data/mawhebty.db`. |
| `SESSION_SECRET` | للإنتاج | سر توقيع رموز الجلسات. استخدم قيمة عشوائية طويلة (32 حرفًا على الأقل). في التطوير يوجد سر مؤقت آمن للتجربة. |
| `AI_API_KEY` | لا | مفتاح أي مزود متوافق مع OpenAI Chat Completions. |
| `AI_BASE_URL` | لا | عنوان المزود المتوافق مع OpenAI. الافتراضي `https://api.openai.com/v1`. |
| `AI_MODEL` | لا | اسم النموذج. الافتراضي `gpt-4o-mini`. |
| `GEMINI_API_KEY` | لا | مفتاح Google Gemini مباشرة (بديل عن `AI_API_KEY`). |
| `GEMINI_MODEL` | لا | نموذج Gemini. الافتراضي `gemini-2.0-flash`. |
| `NEXT_PUBLIC_APP_URL` | لا | رابط التطبيق العام، للاستخدام في الإنتاج. |

بدون أي مفتاح AI، يعمل نوري بالوضع المحلي الآمن. لا تضع مفاتيح حقيقية داخل المستودع أو في ملف يُرفع إلى Git.

## الأمان والصلاحيات

- **كلمات المرور:** تُجزّأ باستخدام `scrypt` مع ملح عشوائي لكل مستخدم، ولا تُخزن أو تُعرض كنص صريح.
- **الجلسات:** رمز عشوائي 32 بايت يُخزن مجزأً بـ SHA-256 في قاعدة البيانات، ويُرسل في كوكي `mawhebty_session` بخاصية `HttpOnly` و`SameSite=Lax`، مع `Secure` في الإنتاج.
- **الصلاحيات:** كل صفحة محمية وكل Server Action تتحقق من الدور على الخادم: `requireChild` و`requireParent` و`requireAdmin` و`requireUser`.
- **ملكية البيانات:** استعلامات الطفل مقيدة بمعرّف المستخدم، واستعلامات ولي الأمر مقيدة بأطفاله المرتبطين به.
- **منع التكرار:** XP يُمنح عبر `xp_transactions` بمرجع فريد لكل مرحلة، داخل معاملة، لذلك لا يمكن جمع المكافأة مرتين حتى مع إعادة الإرسال.
- **فتح المراحل:** يُحسب على الخادم؛ لا يمكن تجاوز ترتيب المراحل من الواجهة.
- **حدود المحادثة:** حد طلبات لكل مستخدم لفترة زمنية، وفلترة للمحتوى غير المناسب، ورفض الرسائل الطويلة.
- **سجل تدقيق:** العمليات الإدارية تُكتب في `audit_logs` من الخادم فقط.
- **حماية إضافية:** تعطيل حساب يُنهي جلساته، ولا يمكن للمسؤول تعطيل نفسه أو آخر مسؤول نشط.

> **ملاحظة:** الجلسات وحدود الاستخدام تُخزن في SQLite/الذاكرة. عند التشغيل على عدة نسخ خادم (instances)، استخدم مخزنًا مشتركًا لحدود الاستخدام (مثل Redis) قبل الإنتاج.

## قاعدة البيانات والبيانات الأولية

- **المحرك:** SQLite عبر `node:sqlite` المدمج في Node، مع WAL و`foreign_keys=ON`.
- **المسار:** `data/mawhebty.db` افتراضيًا، ويمكن تغييره عبر `DATABASE_PATH`.
- **التهيئة:** `ensureSeeded()` تُنشئ المخطط وتزرع البيانات عند أول استخدام، وتُستدعى من طبقات المصادقة والاستعلام.
- **المحتوى الأولي:** 5 مجالات، 29 موهبة، 32 مرحلة كاملة موزعة على 4 مواهب (الرسم، البرمجة، التحدث أمام الجمهور، الكتابة الإبداعية)، 10 أسئلة تقييم، 8 تحديات، 6 شارات، وحسابات عرض.
- **المواهب الأخرى:** موجودة في الكتالوج بصفحات تفاصيل، لكن بعضها لا يملك مسارًا تعليميًا كاملًا بعد. هذا مقصود وموثق، ولا تدّعي الواجهة وجود دروس غير موجودة.

المخطط يشمل: `users`, `profiles`, `user_settings`, `sessions`, `password_reset_tokens`, `talent_categories`, `talents`, `learning_paths`, `stages`, `user_talents`, `user_progress`, `favorites`, `assessment_questions`, `assessment_results`, `badges`, `user_badges`, `activities`, `activity_submissions`, `notifications`, `chat_messages`, `xp_transactions`, `audit_logs`.

## مساعد نوري

- كل الرسائل تمر عبر `POST /api/noori` بعد التحقق من جلسة الطفل ودوره.
- توجد قائمة سماح لمواضيع تعليمية، ورفض للطلبات الحساسة (بيانات شخصية، عنف، محتوى جنسي، نصائح طبية/نفسية خطيرة)، وتحويل لطيف للتحدث مع شخص بالغ موثوق عند الحاجة.
- **مع مفتاح AI:** يستخدم المزود المتوافق مع OpenAI أو Gemini، مع تعليمات نظام عربية واضحة وحدود أمان.
- **بدون مفتاح:** يعمل بمحرك ردود محلي قائم على نية الرسالة، ويظل مفيدًا في شرح الدروس واقتراح الأنشطة والتشجيع.
- نوري **لا يغيّر** النقاط أو التقدم أو الشارات. المحادثات تُحفظ في `chat_messages` ويمكن للطفل أو المسؤول مسحها.

الخلاصة: لا تدّعِ أن AI متصل لمجرد وجود الكود. تحقق من `isAiConfigured()` أو من شارة الحالة في صفحة نوري بعد ضبط المفتاح.

## حدود معروفة

نفضّل الوضوح على الادعاء:

1. **الواجهة عربية فقط.** اختيار الإنجليزية في الإعدادات يُحفظ في الحساب لكنه لا يترجم الواجهة بعد.
2. **البريد غير مُفعّل.** لا يوجد مزود بريد. في وضع التطوير يعرض نموذج استعادة كلمة المرور رابطًا مباشرًا؛ في الإنتاج الرسالة تطلب التواصل مع الدعم بدل ادعاء إرسال بريد لم يحدث.
3. **Supabase غير متصل.** التطبيق يستخدم SQLite محليًا لأن بيانات اعتماد Supabase لم تُقدَّم. راجع قسم الانتقال أدناه.
4. **مزود AI غير متصل افتراضيًا.** يعمل نوري بالوضع المحلي حتى تضع مفتاحًا صحيحًا.
5. **لم يتم النشر.** لا يوجد رابط عام ولا نطاق ولا شهادة SSL جاهزة من هذا المستودع.
6. **ليست كل المواهب تملك مسارًا كاملًا.** 4 مواهب لها 8 مراحل لكل منها؛ الباقي كتالوج قابل للتوسعة من لوحة الإدارة.
7. **PWA أساسية.** يوجد manifest وأيقونة، لكن لا يوجد Service Worker/تخزين دون اتصال كامل بعد.
8. **SQLite مناسبة لخادم واحد.** للتوسع الأفقي أو الاستضافة Serverless متعددة النسخ، انتقل إلى Postgres/Supabase.
9. **حدود الاستخدام في الذاكرة** وقد تُصفَّر عند إعادة تشغيل الخادم.
10. **لا توجد اختبارات E2E آلية بعد.** تم التحقق يدويًا من المسارات الأساسية، ويُنصح بإضافة Playwright قبل الإنتاج.

## الانتقال إلى Supabase أو الاستضافة

الخطة العملية عند توفر بيانات الاعتماد:

1. أنشئ مشروع Supabase وطبّق مخطط الجداول الموجود في `src/lib/db.ts` مع تحويل أنواع SQLite إلى Postgres (`TEXT` → `text`, `INTEGER` → `integer`, `REAL` → `double precision`).
2. انقل البيانات عبر سكربت تصدير/استيراد، مع الحفاظ على المعرّفات العلائقية.
3. استبدل طبقة `db.ts` بعميل Supabase أو ORM (Drizzle/Prisma) مع الإبقاء على واجهة `repository.ts` لتقليل التغييرات.
4. استبدل جلسات الكوكي المخصصة بـ Supabase Auth أو أبقِ الجلسات الحالية مع تخزينها في Postgres بدل SQLite.
5. أضف RLS (Row Level Security) لكل جدول، مع سياسات تمنع الطفل من قراءة بيانات غيره، وتمنع ولي الأمر من قراءة أطفال آخرين.
6. أضف مفاتيح البريد وAI ومزود الاستضافة في متغيرات بيئة الخادم فقط، وليس في كود العميل.
7. أعد تشغيل الاختبارات واختبر كل مسار على بيئة staging قبل الإنتاج.

لا تحفظ `service_role` في متغيرات `NEXT_PUBLIC_*`، ولا تستخدم مفاتيح تجريبية أو وهمية.

## قائمة التحقق قبل الإنتاج

- [ ] تعيين `SESSION_SECRET` عشوائي طويل، وإزالة أي سر افتراضي.
- [ ] تغيير كلمات مرور حسابات العرض أو حذفها.
- [ ] تفعيل HTTPS و`Secure` cookies (مفعل تلقائيًا في الإنتاج).
- [ ] مراجعة سياسة الخصوصية والشروط مع مستشار قانوني مختص.
- [ ] إعداد مزود بريد لاستعادة كلمة المرور، أو تعطيل الخيار بوضوح.
- [ ] إعداد AI أو تأكيد الوضع المحلي في الإنتاج.
- [ ] إضافة نسخ احتياطي دوري لقاعدة البيانات.
- [ ] إضافة مراقبة أخطاء (Sentry أو بديل) وسجلات خادم.
- [ ] إضافة اختبارات E2E لمسارات التسجيل والتقييم والتقدم والإدارة.
- [ ] مراجعة الصلاحيات و RLS بعد الانتقال إلى قاعدة بيانات مشتركة.
